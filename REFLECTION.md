## Project #1: Applicant Tracking System

<b>1. Trace your Django forms</b> One class that inherits from forms.ModelForm is the "CandidateForm" located in hiring/forms.py. This class automatically creates form input for things such as first and last name, phone number, and handles the email uniqueness check. You can trace how it is used by logging in as a staff member and clicking "Log candidate" when adding a new candidate into the system. I searched through the files and could not find a class that inherits from a forms.Form.

<b>2. Trace a many-to-many relationship</b> One many-to-many relationship is the "Job" and "Skill". A single foreign key would not represent this relationship correctly because a single foreign key would limit a job opening to only have one skill required rather than allowing multiple skills for one job, and vice versa with a skill only being allowed to have one job connected. Django automatically built a `hiring_job_skills`. It is a plain association table because it only stores the matching IDs to connect jobs and skills together.

<b>3. Explain one prototype decision</b> The prototype decision I choose is the UI Pipeline Dashboard Prototype. This prototype was built to determine what structural layout out staff would use to manage applicants across pipeline tracking stages. Alternatives explored were multi-column visual board layout but I ended up choosing the dense table layout with per-row HTMX. I choose to go with HTMX based on our last interview as it seemed like the simpler and more efficient way to go. The decision appears under the file hiring/templates/hiring/_pipeline.html.

<b>4. Defend one code-design decision</b> The code-design decision I chose is using a many-to-many relationship to link the job openings and skills together. Options were either a single foreign key relationship or many-to-many. The many-to-many fits perfectly because it allows a job to use multiple skills and vice versa. This relationship prevents database errors from happening. This decision appears in hiring/models.py in the code "skills = models.ManyToManyField".
